## Requirements
### Requirement: Single static artifact serves landing and viewer
The relay's static layer SHALL serve a single HTML document from `public/index.html` that contains both the marketing landing and the collaborative viewer. No additional deploy target, build artifact, or domain is required.

#### Scenario: bare root URL shows landing
- **WHEN** a browser navigates to `/` (no fragment) on the relay host
- **THEN** the response is `public/index.html` and the rendered document displays the landing hero, system-diagram SVG, install snippet, and call-to-action buttons
- **AND** the viewer markup is not visible

#### Scenario: hashless production URL serves landing
- **WHEN** a browser navigates to `https://livedown.dwmkerr.partykit.dev/`
- **THEN** the landing page is rendered (no viewer chrome)

### Requirement: Mode is selected from `location.hash`
The document SHALL choose between landing and viewer mode synchronously on first paint based on `location.hash`. Absent or empty hash selects landing; any non-empty hash selects viewer.

#### Scenario: hash present selects viewer
- **WHEN** the URL is `/#<any-key>`
- **THEN** the viewer markup is rendered and the landing markup is not visible
- **AND** the viewer connects to the room identified by the hash, exactly as before this change

#### Scenario: empty hash selects landing
- **WHEN** the URL is `/#` (hash present but empty) or `/`
- **THEN** the landing markup is rendered

#### Scenario: mode chosen before stylesheet paint
- **WHEN** the document loads
- **THEN** the inactive `<main>` is hidden before first paint (no flash of viewer-on-landing or vice versa)

### Requirement: Hash transitions reflect mode
`hashchange` events SHALL cause the page to render the correct mode for the new hash. A full reload is acceptable for the transition.

#### Scenario: landing → viewer
- **WHEN** the URL changes from `/` to `/#<key>`
- **THEN** the page renders the viewer for the new room (full reload permitted)

#### Scenario: viewer → landing
- **WHEN** the URL changes from `/#<key>` to `/` (hash cleared)
- **THEN** the page renders the landing (full reload permitted)

### Requirement: Viewer assets MAY load on landing mode
This change SHALL NOT regress current asset loading. Third-party viewer assets (CodeMirror, marked, mermaid, tweetnacl) MAY continue to load on landing mode in this iteration. A follow-up change is expected to gate them behind a viewer-mode loader.

#### Scenario: no regression in asset loading
- **WHEN** a browser loads `/` after this change
- **THEN** the set of third-party assets fetched MUST NOT exceed what was fetched before this change

#### Scenario: future deferred-load (informative)
- **WHEN** a future change refactors viewer init to be async
- **THEN** that change MUST move third-party viewer assets behind a hash-gated loader so `/` does not fetch them

### Requirement: Existing share URLs continue to work
All previously generated share URLs of the form `https://<host>/#<doc-key>` SHALL continue to open the viewer at the same room with no functional regression.

#### Scenario: legacy share URL
- **WHEN** a user opens a share URL generated by any prior CLI version
- **THEN** the viewer loads, connects to the relay, and renders the same content it would have rendered before this change

### Requirement: `site/` directory is removed
After this change, the repository SHALL contain no `site/` directory. All landing content lives under `public/`.

#### Scenario: repository layout
- **WHEN** the repository is checked out
- **THEN** `site/` does not exist
- **AND** `public/index.html` contains both landing and viewer markup
