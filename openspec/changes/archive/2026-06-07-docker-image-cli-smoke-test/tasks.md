## 2. Add post-publish smoke step to `deploy-docker`

- [x] 2.1 In `.github/workflows/deploy.yaml`, in the `deploy-docker` job, add a new step **after** the existing `docker buildx imagetools inspect` step and **before** the job ends. Name it `Smoke-test CLI from published image`. **Implemented as:** the step is encapsulated in `.github/actions/docker-smoke-test/action.yml`. The wire-up (`uses:` call) is added to `multi-arch-docker-image/tasks.md` step 3.5b, because the host `deploy-docker` job is created by that change and does not exist on `main` yet. Touching `deploy.yaml` here would either scope-creep into the dependency's territory (stubbing out the whole `deploy-docker` job) or leave a broken workflow file on `main` between the two merges.
- [x] 2.2 The step SHALL run `docker run --rm --platform linux/amd64 "ghcr.io/dwmkerr/livedown:${{ steps.meta.outputs.version }}" --help` and redirect stdout to `"$RUNNER_TEMP/cli-help.txt"` (avoid inline pipe-grep quoting issues per design decision §3 / Risks). **Implemented** in `.github/actions/docker-smoke-test/action.yml`'s `Run --help against published image` step.
- [x] 2.3 After the `docker run`, add a `grep -q '^Usage:' "$RUNNER_TEMP/cli-help.txt"` (or equivalent fixed-string check) and exit non-zero with a clear diagnostic if the marker is missing. Print the captured `--help` output to the job log on failure to make debugging cheap. **Implemented** in `.github/actions/docker-smoke-test/action.yml`'s `Assert usage marker present` step using `grep -qF` for literal-string matching (not anchored, so a leading banner above `Usage:` does not cause a false negative) and `::group::` + `cat` for the failure dump.
- [x] 2.4 Confirm the step does NOT add new permissions or secrets. It pulls a public image; the existing `permissions: { contents: read, packages: write }` block is unchanged. **Confirmed:** the composite action runs only `docker run` and `grep`; no token, no `id-token: write`, no `packages: write` needed for an anonymous public pull. The wire-up step in `deploy-docker` inherits the job's existing permissions block unchanged.
- [x] 2.5 Do not add the smoke step to the PR-time `cicd.yaml` `docker` job (per design Non-Goals — no published image to pull at PR time). **Confirmed:** no edits to `cicd.yaml`. The composite action is wired in only from `deploy-docker`.
