## Context

The OpenSpec flow automates plan and implement stages via GitHub Actions, driving a Claude Code agent. Currently, the agent posts a summary comment and opens a PR, but neither the PR body nor any structured record captures which sub-agents or skills were invoked during the run. Maintainers have no easy way to audit what automation drove each artifact.

The PR body is assembled by the agent during the plan and implement jobs. Changing the PR body format is the minimal intervention point — no new infra is needed.

## Goals / Non-Goals

**Goals:**
- Embed a structured usage table in every spec PR body and every impl PR body.
- Use HTML comment markers so the table can be found programmatically.
- Keep the table human-readable in GitHub's Markdown renderer.
- Minimise the diff to workflow prompts; avoid touching unrelated files.

**Non-Goals:**
- Storing usage data outside the PR body (no database, no separate artefact).
- Retroactively adding tables to existing PRs.
- Validating table contents (agent self-reports; no schema enforcement at runtime).
- Tracking skill invocations at sub-step granularity (one row per top-level step is sufficient).

## Decisions

### D1: HTML comment delimiters as markers

The table is wrapped in `<!-- openspec-flow-usage-table -->` … `<!-- /openspec-flow-usage-table -->`. This matches the existing pattern used for `<!-- openspec-flow-summary -->` and is invisible in rendered Markdown, so it does not affect the visual PR body for readers who don't need the raw HTML.

*Alternative considered*: A dedicated YAML front-matter block — rejected because GitHub does not render front matter and it would appear as raw text at the top of the PR.

### D2: Agent self-reports table rows

The agent (Claude Code) is instructed via the job prompt to produce the table as part of the PR body. This avoids the need for a separate post-processing step or workflow script to introspect the agent's actions.

*Alternative considered*: A wrapper script that intercepts tool calls and logs them — rejected as too fragile and requiring changes to the Claude Code runner invocation.

### D3: Table placement — after recap, before separator

The table appears after the 1–3 sentence recap paragraph and before the `---` separator. This keeps the visual PR summary concise at the top while the table is available for those who scroll or grep the raw body.

### D4: Columns: Step, Agent/Skill, Detail

Three columns cover the essentials:
- **Step** — ordinal or phase name (e.g., "1 – Explore", "2 – Build Spec").
- **Agent/Skill** — the sub-agent or skill name (e.g., `openspec-explore`, `openspec-ff-change`).
- **Detail** — free-text note (e.g., CLI command, key finding, reason invoked).

*Alternative considered*: A flat list of bullets — rejected because a table is easier to scan and parse programmatically.

### D5: Update only agent prompts, not composite actions

The table content is generated by the agent, not by a shell step. Only the prompt strings in `.github/workflows/openspec-flow.yaml` (and any skill files that contain PR-body templates) need updating.

## Risks / Trade-offs

- **Agent faithfulness** → The agent self-reports; it could omit steps or fabricate entries. Mitigation: the prompt instructs the agent to list every sub-agent and skill it invoked, and reviewers can cross-check against the run log.
- **Table grows large for complex runs** → Long tables push the separator and body content down. Mitigation: limit Detail column to a single concise sentence; truncate if necessary.
- **Marker collision** → A human could accidentally include the markers in a manual PR edit. Mitigation: low probability; markers are verbose enough to be unambiguous.

## Migration Plan

1. Update agent prompt in the plan job to include usage table instructions.
2. Update agent prompt in the implement job similarly.
3. Update any skill files whose templates include a PR body template.
4. Validate with `openspec validate show-subagent-skill-usage-table --strict`.
5. Merge; no rollback strategy needed (the change is purely additive to PR body text).
